## แก้โค้ดแล้ว build ใหม่

โค้ดจริงอยู่ใน `src/*.js`, `css/app.css`, `shell.html` แก้เสร็จแล้วรัน `python3 build.py` จะได้ `index.html` ใหม่ (รวมเคสใน `cases/` และกติกาใน `rules/` ไว้ในไฟล์ด้วย) ไม่ต้องติดตั้งอะไรเพิ่ม

เพิ่มเคสโดยไม่ build ก็ได้: วางไฟล์ .md ใน `cases/` แล้วเพิ่มชื่อไฟล์ใน `cases/index.json` หน้าเว็บบน GitHub Pages / Vercel จะโหลดเคสใหม่ให้เอง (เปิดจากไฟล์ในเครื่องต้อง build ก่อน)

## เชื่อม AI ได้ 5 เจ้า (+ OpenAI-compatible อื่น ๆ)

กดปุ่ม **ตั้งค่า AI** มุมขวาบน เลือกผู้ให้บริการแล้วทำตามคู่มือในหน้าต่าง (ขอคีย์ที่ไหน, Base URL, รุ่นที่แนะนำ) ผู้ใช้ใส่ API key เอง

**0. Claude ในหน้านี้** มีเฉพาะตอนเปิดใน claude.ai ไม่ต้องมีคีย์

**1. ใช้ API key ของฉัน (BYOK)** ใช้ได้ทั้ง GitHub Pages และ Vercel คีย์ถูกส่งจากเบราว์เซอร์ตรงไปที่ผู้ให้บริการ ไม่ผ่านเซิร์ฟเวอร์ของเว็บนี้ และจะจำไว้ในเบราว์เซอร์ก็ต่อเมื่อติ๊ก "จำคีย์"

| ผู้ให้บริการ | Endpoint ที่ใช้ | หมายเหตุ |
| --- | --- | --- |
| Claude (Anthropic) | `https://api.anthropic.com/v1/messages` | เรียกจากเบราว์เซอร์ได้ (ส่ง header `anthropic-dangerous-direct-browser-access`) |
| ChatGPT (OpenAI) | `https://api.openai.com/v1/chat/completions` | |
| Gemini (Google) | `https://generativelanguage.googleapis.com/v1beta/models/{model}:generateContent` | |
| OpenRouter | `https://openrouter.ai/api/v1/chat/completions` | |
| OrcaRouter | `https://api.orcarouter.ai/v1/chat/completions` | OpenAI-compatible ถ้าเรียกจากเบราว์เซอร์ไม่ผ่าน (CORS) ให้ใช้โหมดเซิร์ฟเวอร์ |
| OpenAI-compatible อื่น ๆ | ใส่ Base URL เอง | เช่น LLM ในเครื่อง หรือ gateway ของคณะ |

ตั้งรุ่นโมเดล 2 ช่อง: **รุ่นเร็ว** สำหรับเจ้าของสัตว์ (ถูกเรียกทุก turn) และ **รุ่นคิดลึก** สำหรับ AI อาจารย์และการสร้างเคส กด **โหลดรายชื่อรุ่น** เพื่อดึงรายชื่อรุ่นจริงจากบัญชีของคุณ แล้วกด **ทดสอบการเชื่อมต่อ**

**2. ใช้ AI ของเซิร์ฟเวอร์** มีเฉพาะเมื่อ deploy บน Vercel คีย์อยู่ใน Environment Variables นักศึกษาไม่ต้องมีคีย์ของตัวเอง (เหมาะกับใช้ทั้งห้อง)

## Deploy

### GitHub Pages (โหมด BYOK เท่านั้น)

1. สร้าง repo แล้ว push ไฟล์ทั้งหมด (มีไฟล์ `.nojekyll` แล้ว) หรือใช้แค่ไฟล์ `index.html` ไฟล์เดียวก็ได้
2. Settings → Pages → Deploy from a branch → `main` / root
3. เปิด `https://<user>.github.io/<repo>/` ทุกคนใส่คีย์ของตัวเองในหน้า "ตั้งค่า AI"

### Vercel (BYOK + โหมดเซิร์ฟเวอร์)

1. push ขึ้น GitHub แล้วใน Vercel กด **Add New → Project → Import** repo นั้น (Framework: Other, ไม่ต้องตั้ง build command)
2. Settings → Environment Variables:

| ตัวแปร | ค่า |
| --- | --- |
| `LLM_PROVIDER` | `anthropic` / `openai` / `gemini` / `openrouter` / `orcarouter` / `custom` |
| `LLM_API_KEY` | คีย์ของผู้ให้บริการ |
| `MODEL_FAST` | รุ่นสำหรับเจ้าของสัตว์ |
| `MODEL_STRONG` | รุ่นสำหรับอาจารย์และสร้างเคส |
| `LLM_BASE_URL` | เฉพาะ `custom` |
| `ACCESS_CODE` | ไม่บังคับ: รหัสที่ต้องใส่ในหน้าตั้งค่าก่อนใช้ AI ของเซิร์ฟเวอร์ กันคนนอกใช้โควตา |

3. Redeploy หน้าเว็บจะเจอ `/api/llm` และเปิดตัวเลือก "ใช้ AI ของเซิร์ฟเวอร์" ให้เอง
4. ตั้งเพดานค่าใช้จ่ายรายเดือนในคอนโซลของผู้ให้บริการด้วย

## ขั้นตอนใช้งาน

**อาจารย์ (Studio)**
1. **สร้างเคสจาก PDF / รูปถ่าย**: วาง PDF หรือรูป (มือถือกดแล้วถ่ายได้เลย) รูปถ่ายให้ลากกรอบระบายดำข้อมูลส่วนตัวก่อน ใส่ Final diagnosis ที่ยืนยันแล้ว (AI จะยึดโรคนี้ และใช้เวชระเบียนเป็นแรงบันดาลใจให้ใกล้ของจริงที่สุด) · ถ้าเป็น PDF ที่มีตัวอักษร ระบบดึงข้อความในเบราว์เซอร์ แปลงอักษรไทยที่ PDF เก็บเป็นรหัสพิเศษกลับเป็นปกติ และปิดชื่อ เบอร์ อีเมล เลขบัตร HN ไมโครชิป ที่อยู่ วันที่ (เปลี่ยนเป็นวันสัมพัทธ์) → ตรวจและแก้ข้อความก่อนส่ง → เลือก 1 PDF = 1 เคส หรือหลาย PDF = เคสผสม → AI เขียนเคส .md แล้ว AI อีกรอบตรวจหาข้อมูลระบุตัวตน ความสอดคล้องทางคลินิก และจุดสอน
2. **คลังเคส**: กรอง ค้นหา แก้ไฟล์ .md ทดลองคุยเป็นนักศึกษา และกด "ตรวจแล้ว" พร้อมชื่อผู้ตรวจ
3. **แพ็ก Bundle**: ติ๊กเลือกเคส จัดลำดับ ตั้งโควตา บุคลิกเจ้าของ จำนวนครั้งที่ทำได้ และโจทย์เพิ่มรายเคส → ตั้งรหัสห้อง → ได้ `ชื่องาน.vilpack.zip`
4. **ตรวจผล**: ลากไฟล์ `.vilresult.json` ของทั้งห้อง → ตารางคะแนน, Critical miss ที่เจอบ่อย, เรื่องที่ไม่ได้ถามบ่อย, ดาวน์โหลด CSV

**นักศึกษา (Practice)**: วาง `.vilpack.zip` → ใส่ชื่อ รหัสนักศึกษา รหัสห้อง → ทำงานทีละเคส → **ดาวน์โหลดผลเพื่อส่งอาจารย์**

## รูปแบบไฟล์

- **เคส `.md`**: frontmatter (`id, title, species, system, level, quota, urgency, persona, status, version, patient, opening`) + หัวข้อ `## A.` ถึง `## H.` ดูตัวอย่างใน `cases/` เพิ่มเคสเข้าคลังเว็บได้โดยวางไฟล์ใน `cases/` และเพิ่มชื่อไฟล์ใน `cases/index.json`
- **Bundle `.vilpack.zip`**: `manifest.json` (ชื่องาน งาน การ์ดเคส ไม่มีเฉลย) + `cases/t*.vilcase` (เคสเต็ม เข้ารหัส AES-256-GCM ด้วยกุญแจที่สร้างจากรหัสห้องผ่าน PBKDF2)
- **ผล `.vilresult.json`**: บทสนทนา ฟอร์มบันทึก รายการตรวจที่สั่ง คะแนนแต่ละด้าน และ Safety Gate ของทุกครั้งที่ทำ
- **กติกา** ใน `rules/*.md` (กติกาเจ้าของ, การนับ turn, rubric, Safety Gate, ฟอร์ม, Debrief) แก้ข้อความได้โดยไม่ต้องแตะโค้ด

## ข้อจำกัดที่ควรรู้ (ฉบับร่าง)

- **การล็อกเฉลยเป็นแบบกันคนทั่วไป**: เปิด zip แล้วอ่านเฉลยไม่ได้ แต่คนที่รู้รหัสห้องและแกะโค้ดในเบราว์เซอร์ยังดึงเฉลยออกมาได้ ถ้าต้องใช้สอบจริง ต้องย้ายการถอดรหัสและการให้คะแนนไปฝั่งเซิร์ฟเวอร์
- **ไฟล์ผลยังไม่มีลายเซ็น**: นักศึกษาที่ตั้งใจแก้ไฟล์ JSON แก้คะแนนได้ ใช้เป็นแบบฝึก ไม่ใช่คะแนนสอบ
- **การปิดข้อมูลส่วนตัวใช้รูปแบบข้อความ**: ชื่อที่ไม่มีป้ายกำกับอาจหลุด ต้องให้อาจารย์ตรวจทุกครั้ง และ PDF ที่เป็นภาพสแกนปิดอัตโนมัติไม่ได้ ควรระบายดำก่อนอัปโหลด
- **PDPA**: การนำเวชระเบียนจริงมาใช้และส่งข้อความไปยังผู้ให้บริการ AI ควรผ่านความเห็นชอบของคณะหรือเจ้าของข้อมูลก่อน
- **ความคืบหน้าของนักศึกษา**เก็บในเบราว์เซอร์ ปิดแล้วเปิด zip เดิมพร้อมรหัสห้องก็ทำต่อได้ แต่ถ้าเปลี่ยนเครื่องต้องเริ่มใหม่
- **ค่าแล็บในคลังตัวอย่าง 10 เคส**เป็นค่าจำลอง ยังรอคณาจารย์ตรวจทาน (สถานะ `draft`)
